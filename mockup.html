Renderer models are approximations for design purposes: macOS = no hinting, greyscale AA only (no subpixel since Mojave), slight stem darkening; Chrome on Windows (DirectWrite) = vertical grid‑fitting only, ClearType subpixel AA; FreeType v35 = full horizontal + vertical grid‑fitting (closest to Windows GDI), LCD‑filtered subpixel AA, or 1‑bit below the threshold in greyscale mode. With Subpixel on, zoomed cells show each pixel as its three RGB stripes as a monitor would light them, and actual‑size views show the resulting colour fringes. Chrome on macOS uses the macOS renderer. The reference row is the browser's own rendering of your reference font.

Build spec — CrispFonter for macOS

Everything needed to implement the app shown above as a native macOS app. The prototype's JavaScript on this page is the reference implementation of the geometry, grid‑fitting and renderer models; port it, don't reinvent it. Read the page source when a detail below is ambiguous.

1. Goal and constraints

  • A document‑based macOS app for drawing monospaced programming fonts that stay legible at small sizes: draw a stroke skeleton on a dot grid → thicken the strokes → add hint points → preview at small sizes against a reference font → export a hinted TrueType .ttf.
  • Swift 5 / SwiftUI, macOS 15+, Xcode 16+. Use stock controls everywhere (segmented control, sliders, steppers, popups, NSFontPanel, NSSavePanel, NSMenu for context menus, standard toolbar). The only custom view is the editor canvas (an NSView drawn with CoreGraphics, hosted via NSViewRepresentable).
  • Keep the code simple. No third‑party dependencies. Prefer plain functions over abstractions. Target ≈3–4k lines total.
  • Repository state: CrispFonter.xcodeproj (hand‑written, uses file‑system‑synchronized groups so any file added under CrispFonter/ or CrispFonterTests/ is compiled automatically), CrispFonter/Info.plist (document type com.crispfonter.project, extension .crisp), CrispFonter/App/ProjectDocument.swift (a ReferenceFileDocument with an undoable mutate helper), CrispFonter/Model/FontProject.swift (the data model below, final), CrispFonter/Geometry/Outline.swift (contour/outline types with CGPath conversion). Everything else is to be written.

2. Data model (already in Model/FontProject.swift)

FontProject      unitsPerEm=1000, gridDivisions=16 (cells per em), metrics, defaultWeight=1.5 (grid units, whole stroke),
                 glyphs [UInt32: Glyph], referenceFontName, previewText, previewSize (6–18, step 0.5),
                 previewRenderer, previewLCD, pixelGridSize, previewSizes [9,11,13,16], export
Metrics          ascender 12, capHeight 11, xHeight 8, descender −4, lineHeight 19, defaultAdvance 9   (grid units)
Glyph            scalar (0 = .notdef), advance: Int? (nil → default), paths [SkeletonPath], hints [UUID: HintPoint], complete
SkeletonPath     nodes [Node], closed
Node             id, p (GridPoint), kind corner|smooth, cIn/cOut (absolute handle positions or nil),
                 left/right: Double? (ratio of default half‑weight; nil = 1; 0 pins that edge to the skeleton),
                 angle (degrees, cross‑section rotation for angled terminals), cap (grid units the end bulges; 0 = flat)
HintPoint        x: SnapMode?, y: SnapMode?     SnapMode = nearest | negative | positive

All coordinates are in grid units, y up, baseline at 0, left sidebearing at x=0. Font units = grid × (unitsPerEm / gridDivisions). Save as pretty‑printed JSON. Every edit goes through ProjectDocument.mutate so ⌘Z works.

3. Window layout

One window per document, three panes (HSplitView): sidebar 200 pt · editor (flexible) · right panel 400 pt.

SidebarGlyphs: 6‑column grid of buttons in FontProject.glyphOrder (.notdef shown as ▯, space as ␣). Click selects; double‑click toggles complete. Styles: undrawn = faint; drawn = normal on a subtle tint; complete = green tint; current = accent outline. ←/→ step glyphs.
Metrics: steppers (integers, grid units) for ascender, cap height, x‑height, descender, advance width, line height.
Reference font: popup of monospaced families (NSFontManager families with fixed‑pitch trait) plus "Other…" → NSFontPanel.
Rendering model: "Subpixel (RGB stripes)" checkbox; "1‑bit below [N] pt" stepper (greyscale only).
EditorHint‑mode bar (only in Hint mode): "Auto‑detect hint points", "Remove all", status text. Canvas. Status bar: Fill / Skeleton checkboxes; "Pixel grid at [slider 6–18 step 0.5] pt"; cursor grid position; "N paths · N nodes · N hint points". A one‑line help text for the current mode.

Text preview: size slider 6–18 step 0.5 with value; renderer popup; a canvas rendering previewText; a TextEditor for the text.

4. Editor canvas

View transform: fit the box x∈[−3, advance+3], y∈[descender−2, ascender+2] into the view (equal scale both axes); ⌘0 refits; scroll‑wheel zooms, space‑drag pans. Draw in this order: dot grid (dot every cell, bigger every 4th; optional pixel grid overlay = orange lines every gridDivisions/pixelGridSize cells from the origin), blue guides with labels (ascender, cap height dashed, x‑height, baseline heavier, descender) and the two sidebearing verticals (x=0 and x=advance), the derived stems (Hint mode), the translucent fill of the outline (nonzero winding), the skeleton (violet 2 pt), handles (teal, dashed stem, 6 pt square), nodes (hollow: circle = smooth, square = corner; filled when selected), then mode‑specific handles.

Skeleton mode (pen tool)

  • Snap cursor to whole grid; ⇧ or the ½‑grid option snaps to halves.
  • Mouse‑down not on anything: start a new path with a corner node (or append to the path being drawn). Dragging ≥0.5 cell before mouse‑up turns it smooth and sets cOut = cursor, cIn = mirror (⌥ leaves cIn alone).
  • While drawing: click on the last node again, double‑click, ⏎ or ⎋ finishes the path; click on the first node (≥3 nodes) closes it. A dashed rubber band follows the cursor from the last node.
  • Not drawing: drag a node (its handles move with it), drag a handle (smooth nodes keep the opposite handle collinear at its own length unless ⌥), ⌫ deletes the selected node (paths with <2 nodes are removed).
  • Segments: a segment is a straight line iff a.cOut == nil && b.cIn == nil; otherwise a cubic with missing controls equal to the node position.

Thicken mode

  • Each node shows two round orange handles on its cross‑section at distance halfL = (left ?? 1)·weight/2 and halfR along ±(left normal rotated by angle). Ringed when ratio ≠ 1 or angle ≠ 0.
  • Drag a side handle: thickness = projection of cursor onto that handle's direction, clamped ≥0, snapped to ¼ grid, stored as ratio = t / (weight/2). ⌘‑drag sets both sides. ⌥‑drag rotates the cross‑section: angle = atan2(cross(dir0,v), dot(dir0,v)) snapped to 15°, clamped ±75°. Double‑click resets left/right/angle.
  • Open‑path ends show a square cap handle at node + outwardTangent(rotated by angle) × cap (on the node when flat). Drag along that direction sets cap (≥0, ¼ steps); double‑click → 0.

Hint mode

  • Click a node → toggle hint with defaultHint (see §6). Click on a segment (not a node) → insert a node there (line: projected point rounded to ¼; curve: de Casteljau split at t, new node smooth with the split handles, neighbours' handles updated) and hint it. ⌥‑click resets to default. Right‑click → NSMenu: Horizontal (x): Off / Nearest pixel edge / Push left / Push right · Vertical (y): Off / Nearest / Push down / Push up · Remove hint · Delete node.
  • Drag a hint point ≥12 pt: for each axis whose component is ≥40 % of the drag length set positive (right/up) or negative (left/down); other axis unchanged.
  • Drawing: hinted node filled orange with a halo; double‑headed arrow on an axis = nearest, single‑headed = push in that direction. Also draw the derived stems as faint orange bands. Entering Hint mode turns the pixel‑grid overlay on.
  • "Auto‑detect": for every node whose incoming or outgoing tangent is within 20° of vertical or horizontal, set defaultHint. "Remove all" clears. Both are single undo steps.

5. Geometry: skeleton → outline

Port flatten, offsetSide, capPoints, outline from the page script.

  1. Flatten each path to samples {p, halfL, halfR, angle}: lines → 2 samples, cubics → 25 samples (t = 0…1 in 24 steps); halfL/halfR/angle linearly interpolated between the segment's end nodes. Drop the duplicated last sample of closed paths.
  2. Offset the polyline on each side: at sample i take the unit normals of the previous and next segment (n1, n2; at an open end use the one that exists), miter direction m = normalize(n1+n2), scale = min(1/max(0.2, m·n1), 3); if the sample's angle ≠ 0 rotate m by it. Offset point = p + m·d·scale where d = halfL (left, side +1) or halfR (right, side −1).
  3. Contours: closed skeleton → two contours (left offsets; right offsets reversed). Open skeleton → one contour: left forward, end cap, right backward, start cap. Cap from edge A to edge B bulging cap along the (angle‑rotated) outward tangent: 7 points of the half‑ellipse mid + half·cos(a) + out·cap·sin(a), a = π·i/8; none when cap = 0.
  4. Fill with nonzero winding; overlapping strokes need no boolean union. For the editor and rasteriser a polygon is fine. For export convert to TrueType quadratics: fit each run of samples between skeleton nodes with quadratic Béziers (split until max deviation < 1 font unit) — or, simplest acceptable version, emit the polygon points as on‑curve points. Orientation: make outer contours clockwise (y‑up) and set the OVERLAP_SIMPLE glyph flag.

6. Hints → grid‑fitting (preview) and TrueType (export)

defaultHint(node): x = "nearest" if any adjacent tangent is within ~20° of vertical (|t.x| < 0.35)
                   y = "nearest" if any adjacent tangent is within ~20° of horizontal (|t.y| < 0.35)
                   neither → both nearest
edgesAt(node):     e1 = p + left·halfL, e2 = p − left·halfR   where left = leftNormal(tangentAt(node)).rotated(angle)
derivedHints:      for each hinted node and each hinted axis a:
                     if |e1.a − e2.a| > 0.1 → stem {lo, hi, mode} on that axis   else → point anchor {at: p.a, mode}
snapPx(v, mode):   nearest → round(v); positive → ceil(v); negative → floor(v)

Grid‑fitter (fitOutline in the script): scale outline to pixels (s = ppem/gridDivisions). Build one monotone piecewise‑linear map per axis from anchors {src, dst}, sorted by src, dropping any anchor that would break monotonicity; values outside the anchors shift by the nearest anchor's delta. Y anchors (when the renderer hints y): every zone z → round(z·s); each horizontal stem: w = max(1, round(hi−lo)); mode positive → hiP = ceil(hi), loP = hiP−w; negative → loP = floor(lo), hiP = loP+w; nearest → if an edge is within 0.6·s of a zone, that edge takes the zone's target and the other follows, else loP = round(lo); plus point anchors. X anchors (only FreeType model): vertical stems the same way without zones, plus point anchors. Apply the maps to every outline point. Advance = round(adv·s) for FreeType, fractional otherwise.

Rasteriser (rasterize): bitmap w = ⌈adv·s⌉+3, h = base + ⌈−desc·s⌉+2 with base = round(asc·s)+1 rows from the top; glyph origin at pixel x=1. Supersample 4× vertically and 4× per subpixel horizontally (12× per pixel) into a CGBitmapContext, fill nonzero (macOS model also strokes the path with width 0.44 px = 0.22 dilation). Average to per‑subpixel coverage. If LCD is on and the model supports it apply FreeType's 5‑tap filter [8,77,86,77,8]/256 across subpixels; grey coverage = mean of the three subpixels; in greyscale mode FreeType below the 1‑bit threshold thresholds coverage at 0.5. Cache bitmaps by (glyph revision, weight, ppem, renderer, lcd).

Display: zoomed cell = each pixel drawn as three vertical stripes coloured (light,0,0), (0,light,0), (0,0,light) with light = 255·(1−coverage) — a lit white screen, pixelated scaling, integer zoom that is a multiple of 3; greyscale mode draws grey blocks instead. Actual size and text preview: pixel colour = (1−cR, 1−cG, 1−cB) on white. Reference row: CoreText glyph at the same ppem into a bitmap with setShouldSmoothFonts(false), drawn with the same zoom.

TrueType compile (per glyph, executed at every ppem by Windows/FreeType; macOS ignores it): find outline point indices at each hinted edge (record, when building the outline, which skeleton node and side produced each point). Program: SVTCA[y]; for each zone‑anchored or nearest edge MIAP[rnd] to the zone's cvt entry / MDAP[rnd]; for a stem, from the anchored edge MIRP[min,rnd,black] to the other edge with the stem width's cvt entry; for positive/negative modes wrap the MDAP in RUTG/RDTG … RTG; ALIGNRP/SHP the remaining points on the same edge; IUP[y]. Then the same for x with SVTCA[x] and IUP[x]. cvt: one entry per zone height (font units) and per distinct stem width rounded to the nearest grid unit. prep: SCANCTRL/SCANTYPE dropout control; if MPPEM > hintCutoffPPEM then INSTCTRL off. gasp: below gaspMonoThreshold → GRIDFIT only; above → GRIDFIT | DOGRAY | SYMMETRIC_GRIDFIT | SYMMETRIC_SMOOTHING. Write a tiny assembler for just these opcodes (PUSHB/PUSHW/NPUSHB, SVTCA, SRP0/1/2, MDAP, MIAP, MDRP, MIRP, ALIGNRP, SHP, IUP, RTG, RUTG, RDTG, MPPEM, GT, IF/EIF, INSTCTRL, SCANCTRL, SCANTYPE).

7. TrueType export

NSSavePanel → write tables head, hhea, maxp, OS/2, hmtx, cmap (format 4), loca (long), glyf, name, post (format 3), gasp, cvt, fpgm (empty ok), prep with correct checksums and checkSumAdjustment. Glyph 0 = .notdef (the user's drawing, or a hollow box if undrawn), glyph 1 = space (empty, advance only), then every drawn glyph in glyphOrder. Advance = (advance ?? defaultAdvance)·unitsPerCell. hhea/OS/2 ascender/descender/lineGap from metrics (lineGap = lineHeight − ascender + descender). Export sheet options: include hints, 1‑bit threshold, hint cut‑off ppem, family/style names.

8. Text preview

Monospaced layout: advance = round(defaultAdvance·s) px, line height = round(lineHeight·s) px, first baseline at 8 + round(ascender·s). For each character: if that glyph is drawn, draw its cached bitmap for the selected renderer at (x−1, baseline−base); otherwise draw the character with the reference font in grey via CoreText. Re‑render on any change (debounce ~40 ms while dragging).

9. Verification

  • Unit tests: JSON round‑trip of FontProject; outline of a straight vertical stroke of weight 2 at x=4 has edges at x=3 and x=5; a node with left=0 has an edge exactly on the skeleton; grid‑fitter maps a stem [3.2, 4.7] px (w = round(1.5) = 2) to [3, 5] with nearest, to [3, 5] with positive (hiP = ceil(4.7) = 5), and a stem [3.4, 4.1] px (w = 1) to [3, 4] nearest, [4, 5] positive, [3, 4] negative; TrueType writer output re‑parses (table directory, checksums, loca/glyf lengths, cmap lookups).
  • Manual: draw n, add a shoulder hint pushed up+right, confirm the FreeType row squares the arch at 9–11 pt while the macOS row does not; export, open the .ttf in Font Book; if Homebrew freetype is present, render the exported font with a small C harness (FT_LOAD_TARGET_MONO, FREETYPE_PROPERTIES=truetype:interpreter-version=35) and compare with the FreeType row.
